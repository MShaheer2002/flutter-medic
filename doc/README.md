## Where things stand right now

**Phase 1 is complete** (orchestration server, tool routing, device detection, launch/interact/observe, console log capture — all built and verified against a real device; see 003–009). **Phase 2's core architecture is proven**, not just built: given only a plain-language goal, an AI agent used the granular tools (`launch_app`/`observe`/`enter_text`/`tap`) to explore `crash_demo_app`, reasoned entirely from tool-observed evidence (recognized a login form, filled it in, then read a real crash out of `observe`'s output), and — as of 013 — hands off to `reproduce` for a reproduced, confirmed verdict against the same running app, no relaunch needed. Zero pre-written steps, zero prior-knowledge shortcuts in the reasoning chain (012).

The orchestrator exposes two distinct modes: `investigate` (self-contained — give it exact steps and an expected element, it launches, reproduces 3x, and closes) and six granular tools — `launch_app`, `tap`, `enter_text`, `observe`, `hot_restart`, `reproduce`, `close_app` — that hold session state across calls so a calling agent can explore a screen, decide what it means, verify what it found against the same running app, and close when actually done. `observe` returns raw evidence with no anomaly rules applied; judgment is the calling agent's job. The reproduction loop itself (`reproduction.ts`) is shared between both modes — `investigate` owns the launch/connect/close lifecycle around it, `reproduce` reuses an already-open one.

**Confirmed across two demo apps, three distinct bug shapes**: `killer_demo_app`'s silent state bug (caught only by `expected-element-missing`), a fire-and-forget async exception (caught only by `native-log-exception`, 007/009), and `crash_demo_app`'s synchronous build-crash (caught by `runtime-exception`, the primary VM-service rule, proven for the first time against a real, non-injected bug — 012).

**Confirmed in Phase 0**: OBSERVE → ACT → OBSERVE works via Marionette on two different physical devices. MCP server scope (`local` vs `project`) matters for onboarding UX. Patrol MCP does not work reliably in this environment — root cause not found despite an exhaustive investigation (003/004) — not a blocker; the core loop needs only Marionette + Dart MCP.

**Next up (not yet decided)**: tier-2 (baseline diff) or tier-3 (explicit LLM-judgment layer, beyond what the granular tools already enable informally) anomaly detection, `flutter-medic init` (§14), a `screenshot` tool to round out the evidence bundle (§8.3, Phase 3 scope pulled forward), or moving toward CI/headless usage (Phase 6).
